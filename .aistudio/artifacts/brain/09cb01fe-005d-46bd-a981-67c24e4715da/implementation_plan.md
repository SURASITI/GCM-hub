# แผนปรับปรุงสถาปัตยกรรมการดึงข้อมูล Firestore (Firestore Quota & Cache Optimization)

แผนการปรับปรุงระบบดึงข้อมูลจาก Cloud Firestore สำหรับ GCMP Innovation Hub เพื่อแก้ปัญหาโควตาการอ่าน (Read Quota Limit) อย่างถาวร โดยเปลี่ยนจาก Real-time Listener (`onSnapshot`) มาเป็น One-time Fetch (`getDocs`) ควบคู่กับ Cache-First Strategy และแยกการโหลดข้อมูลความคิดเห็น (Comments) เป็นแบบ On-Demand เมื่อผู้ใช้คลิกเปิดดูเท่านั้น

## การตัดสินใจหลักที่ได้รับการยืนยัน (Confirmed Decisions)

> [!IMPORTANT]
> - **การดึงข้อมูลรายการแอปหลัก**: เปลี่ยนจาก `onSnapshot` เป็น `getDocs` ร่วมกับ `localStorage` แคชในเครื่อง ทำให้เปิดหน้าเว็บได้ทันที (Instant Load) และลดจำนวน Read ลงได้มากกว่า 90-95%
> - **การโหลดความคิดเห็น (Comments)**: เปลี่ยนเป็นแบบ On-Demand โหลดเฉพาะเมื่อผู้ใช้งานคลิกปุ่มขยายความคิดเห็นในแอปนั้นๆ โดยหน้าแรกจะแสดงเฉพาะตัวเลขจำนวนความคิดเห็น (`comments: number`) ที่อยู่ในการ์ด
> - **กลไกการอัปเดตข้อมูล (Data Invalidation & Refresh)**: เพิ่มปุ่ม Refresh ข้อมูลในแถบเครื่องมือสำหรับผู้ดูแลระบบและผู้ใช้งาน และอัปเดต Local State แบบทันที (Optimistic Update) เมื่อมีการสร้าง แก้ไข หรือลบแอป โดยไม่ต้องโหลดรายการใหม่ทั้งหมดจากฐานข้อมูล

---

## 1. ภาพรวมและแนวคิดหลัก (Overview & Core Concept)

- **ปัญหาเดิม**: การใช้ `onSnapshot` แบบเรียลไทม์คอยฟังคอลเลกชัน `projects` ทั้งหมด จะทำให้ทุกครั้งที่ผู้ใช้เข้าชมเว็บหรือเปิดแท็บใหม่ Firestore จะนับการอ่านตามจำนวนเอกสารทั้งหมด (68 reads ต่อ 1 เซสชัน) เมื่อมีพนักงานเข้าชมเว็บพร้อมๆ กันหลายคนต่อวัน จึงทำให้เกิน Free Quota 50,000 reads/วัน
- **แนวทางแก้ไขใหม่**:
  1. โหลดข้อมูลจาก Local Cache ในเครื่อง (`localStorage`) ขึ้นแสดงผลทันทีภายใน 0 วินาที
  2. สั่ง `getDocs` เพียงครั้งเดียวเมื่อเริ่มต้น หรือเมื่อผู้ใช้สั่งรีเฟรช
  3. บันทึกผลลัพธ์ลง Local Cache และ IndexedDB (`persistentLocalCache`)
  4. หน้าบัตรแอปแสดงเฉพาะสรุปสถิติ ส่วนรายการข้อความคอมเมนต์จะถูกดึงเมื่อผู้ใช้คลิกเปิดดูเท่านั้น

## 2. ประสบการณ์ใช้งาน (User Experience & Flow)

```
[ผู้ใช้เปิดเว็บ] ──> [ดึงข้อมูลจาก Local Cache แสดงผลทันที 0 วินาที]
        │
        ├──> [เบื้องหลัง: เรียก getDocs เพียงครั้งเดียวเพื่อเช็คข้อมูลล่าสุด]
        │
        ├──> [ผู้ใช้เลื่อนดู / ค้นหา / กรองหมวดหมู่: ทำงานบน Client State ลื่นไหล ไม่คิด Read]
        │
        └──> [ผู้ใช้คลิกไอคอน 💬 เพื่อดูความคิดเห็น]:
                 ├──> [เช็คว่าโหลดคอมเมนต์ของแอปนี้ไว้แล้วหรือยัง]
                 ├──> ถ้ายัง: โหลดคอมเมนต์เฉพาะของแอปนั้น (On-Demand Fetch)
                 └──> แสดงผลกล่องข้อความและรายการความคิดเห็น
```

- **Instant Load**: ผู้ใช้ไม่ต้องรอโหลด Spinner นาน เพราะมีข้อมูลจากแคชแสดงทันที
- **Responsive Filtering**: การค้นหาและสลับแท็บหมวดหมู่ (เช่น MN, ALL) รวมถึงการแบ่งหน้า (Pagination 12/24/48) ทำงานบนหน่วยความจำในเครื่อง ไม่ส่ง Request ไปยังเซิร์ฟเวอร์
- **Refresh Control**: มีปุ่ม "รีเฟรชข้อมูล" (พร้อมเวลาที่อัปเดตล่าสุด) ให้ผู้ใช้กดเพื่อซิงก์ข้อมูลใหม่จาก Cloud ได้ตลอดเวลา

## 3. สถาปัตยกรรมทางเทคนิคและการจัดการข้อมูล (Technical Architecture)

```
┌─────────────────────────────────────────────────────────────┐
│                      Client Browser                         │
│                                                             │
│  ┌───────────────────────┐       ┌───────────────────────┐  │
│  │     ProjectContext    │       │     Local Storage     │  │
│  │   (Global App State)  │<─────>│  (gcmp_cached_v2)     │  │
│  └──────────┬────────────┘       └───────────────────────┘  │
│             │                                               │
│    On App Load (Once)                                       │
│    or Manual Refresh                                        │
│             ▼                                               │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  getDocs(query(projects, orderBy('createdAt', desc))) │  │
│  └──────────────────────────┬────────────────────────────┘  │
└─────────────────────────────┼───────────────────────────────┘
                              │
                    HTTPS Query (One-time)
                              │
                              ▼
        ┌───────────────────────────────────────────┐
        │             Cloud Firestore               │
        │                                           │
        │   projects/ (Metadata & Counts)           │
        │      ├── title, category, url, logo...    │
        │      ├── votes: 12, comments: 4           │
        │      └── favoritedUserIds: [...]          │
        │                                           │
        │   On-Demand Subcollection or Doc Details: │
        │      └── projects/{id}/comments           │
        └───────────────────────────────────────────┘
```

### การเปลี่ยนแปลงในแต่ละไฟล์:

1. **`src/context/ProjectContext.tsx`**:
   - เปลี่ยนจาก `onSnapshot` มาเป็นฟังก์ชัน `fetchProjects(forceRefresh = false)` โดยใช้ `getDocs`
   - เรียก `fetchProjects()` เมื่อ Component Mount ครั้งเดียว
   - ฟังก์ชัน `commentProject` และ `voteProject`: อัปเดตเอกสารเฉพาะรายการนั้นใน Firestore และอัปเดต Local State ทันทีแบบ Optimistic Update
   - เพิ่มฟังก์ชัน `fetchProjectComments(projectId)` เพื่อโหลดคอมเมนต์เฉพาะแอปที่ถูกคลิก
   - เพิ่ม `refreshProjects()` และ `lastUpdated` timestamp เพื่อส่งให้ UI

2. **`src/components/ProjectCard.tsx`**:
   - ปรับสถานะการขยายกล่องคอมเมนต์ (`isCommentsExpanded`): เมื่อผู้ใช้คลิกเปิด จะเรียก `fetchProjectComments` ถ้ายังไม่มีคอมเมนต์ในเครื่อง
   - แสดงสถานะ Loading เล็กๆ ขณะดึงข้อความคอมเมนต์เฉพาะแอปนั้น

3. **`src/components/TopBar.tsx` / `src/components/ProjectGallery.tsx`**:
   - เพิ่มปุ่มไอคอน Refresh ขนาดกะทัดรัด พร้อม Tooltip แสดงสถานะข้อมูลล่าสุด

## 4. แผนการตรวจสอบและยืนยันผล (Verification Plan)

1. **การตรวจสอบการคอมไพล์ (Code Compilation & Lint)**:
   - รัน `lint_applet` เพื่อตรวจทาน Typescript และ Syntax ให้ไม่มีข้อผิดพลาด
   - รัน `compile_applet` เพื่อยืนยันว่าโปรเจกต์ Build ผ่านอย่างสมบูรณ์
2. **การทดสอบฟังก์ชันการทำงาน (Functional Tests)**:
   - ทดสอบเปิดหน้าเว็บ: ข้อมูลแอปทั้ง 59-68 รายการต้องแสดงผลได้ครบถ้วนทันที
   - ทดสอบค้นหา กรองหมวดหมู่ และเปลี่ยนหน้า Pagination
   - ทดสอบการกดขยายคอมเมนต์: คอมเมนต์ต้องโหลดขึ้นมาแสดงผลได้อย่างถูกต้อง และสามารถส่งคอมเมนต์ใหม่ได้
   - ทดสอบการกดหัวใจ (Favorite) และการกดโหวต (Vote) ต้องซิงก์ได้อย่างแม่นยำ
   - ตรวจสอบ Network/Console ว่าไม่มีการยิง Snapshot ติดค้างซ้ำๆ
